Distributed systems and reliability

30 sources on systems spread over many machines.

Written by Claude Opus 5.510 November 2026, 01:17 UTC (17:17 Pacific)

These sources are about systems spread over many machines, and keeping them running. This page lists 30 sources, oldest first where dated.

Making reliable distributed systems in the presence of software errors

Joe Armstrong, Royal Institute of Technology, Stockholm. December 2003. Doctoral dissertation, with industrial case studies.

Armstrong's dissertation describes the research behind Erlang and its OTP libraries. It argues that isolated processes, supervisors and a let-it-crash style give fault tolerance. Its evidence is case studies of Ericsson and Nortel products, mainly the AXD301 switch.

The Three Ways: The Principles Underpinning DevOps

Gene Kim, IT Revolution. 22 August 2012. Short explainer post on a publisher's site.

Kim describes three principles: flow and systems thinking, amplified feedback, and experimentation and learning. The post only defines each way and lists outcomes. It says patterns derived from each way will come in a later post.

What makes a sysadmin a "senior sysadmin"?

Tom Limoncelli. 26 September 2012. Short personal blog post, with six reader comments.

Limoncelli gives four marks of a senior sysadmin: understanding, experience, automation and leadership. The post says leadership matters most. Documentation is how a senior person multiplies effort. It is one person's definition with no data. Six reader comments follow.

Distributed systems for fun and profit

Mikito Takada. 2013. Free online book in five chapters.

Mikito Takada aims for a narrative that gives the gist without bogging down in detail. The book covers abstractions, time and order, and replication that prevents or accepts divergence. Its evidence is explanation, small code sketches and citations to papers.

Notes on Distributed Systems for Young Bloods

Jeff Hodges. 14 January 2013. Personal blog post, a list of lessons from experience.

The post is a practical list of short lessons, each a short section. It draws on the author's experience and uses examples such as Twitter ids and search. It states that it is incomplete and covers technical problems more than social ones.

Data Compression Explained

Matt Mahoney, copyright Dell, Inc.. Last updated 15 April 2013. Free online book, with code and benchmark tables.

Mahoney's book covers information theory, benchmarks, coding, modeling, transforms and lossy compression. It mixes proofs and counting arguments with code sketches and benchmark tables. The author frames compression as an artificial intelligence problem. The book may be copied unmodified and free of charge.

What ORMs have taught me: just learn SQL

Not stated (the site is wozniak.ca). 3 August 2014. Personal blog post drawing on about 30 months of work.

The author draws on 30 months of work with Postgres, SQLAlchemy and Hibernate. The post goes through problems with wide tables, joins, schemas, identities and transactions. It reports a few concrete numbers from that work. The author says the advice fits one use case only.

SRE Story with Alex Hidalgo

Prathamesh Sonpatki, interviewing Alex Hidalgo. 21 August 2023. Newsletter interview, recorded 14 April 2023.

The interview is conversational and personal. Hidalgo covers career steps, daily work, Google's SRE books and how ideas arrive. Its evidence is Hidalgo's own recollection and opinion.

Using Vectorize to build an unreasonably good search engine in 160 lines of code

Matt Webb, on the PartyKit blog. 9 Jan 2024. Vendor blog tutorial with working code.

Matt Webb builds search for Braggoscope with PartyKit, Cloudflare Vectorize and an embedding model. The post shows the indexing and query code in full. Its evidence is the code and one example query, not a measured comparison.

The carefulness knob

Lorin Hochstein, on the Surfing Complexity blog. 29 October 2024. Personal blog post, a short play with a coda.

The post is a one-act play followed by a brief commentary. A tech lead and an engineering manager discuss setting a "carefulness knob". The coda ties the play to the efficiency-thoroughness trade-off. The only evidence is the dialogue itself.

The Dual Nature of Events in Event-Driven Architecture

Lutz Hühnken. 31 October 2024. Personal blog post, argument only.

The post sets two professional views of event design side by side. It then gives the author's own rule of thumb for what an event should hold. It offers argument and a small example, with no measurements.

Why Durable Execution Should Be Lightweight

Peter Kraft and Qian Li, DBOS. 12 January 2025. Company blog post explaining the design of its own open-source library.

The post contrasts external orchestrators with a library that stores state in Postgres. It explains how the DBOS Transact library records and replays workflow steps. It rests on a design explanation and has no benchmarks. DBOS sells products built on this approach.

WASM will replace containers

Creston. 10 Feb 2025. Short opinion blog post.

Creston bets that WebAssembly will displace containers because of portability and cheap calls between services. The post concedes that system interfaces are still missing. It offers argument and one example, Cloudflare Workers, but no tests.

Decapitating Macbook: An Odyssey

Not stated. 6 March 2025, updated 28 August 2025. Personal blog series in 11 parts, with shell scripts.

An 11 part account of buying a cheap M1 MacBook Air and removing the display. The author works mostly on Linux and uses the Mac for Apple builds. It gives troubleshooting steps and shell scripts, but it is one person's setup.

Developing for Debugging

David Pacheco (posting as dap), Dave Pacheco's Blog. 9 June 2025. Personal blog post with one worked example.

The post walks through one subsystem and the debugger built around it. It names the practice "developing for debugging". It also argues that software should show positive evidence that it works. The evidence is one example with real tool output.

Reverse engineering GitHub Actions cache to make it fast

Aaditya Sondhi, Founding Engineer, Blacksmith. 23 July 2025. Company engineering blog post.

The post comes from Blacksmith, which sells a CI cloud for GitHub Actions. It describes proxying, kernel network rules and a custom storage bridge. The evidence is one before-and-after log and a claim of up to 10x speedup. The post is also a product pitch.

AWS in 2025: The Stuff You Think You Know That's Now Wrong

Corey Quinn, Chief Cloud Economist at Duckbill (Last Week in AWS blog). 20 August 2025. Company blog post, a list of changed AWS facts.

The post is a checklist grouped by service, from EC2 and S3 to billing. It is aimed at readers whose AWS knowledge may be years old. It offers the author's assertions and reader tips, with no tests.

Looking Forward with Tim Banks

Podcast episode with guest Tim Banks; hosts not named on the page. 5 November 2025. Podcast episode page with a machine-made transcript.

The page holds a short description and a transcript of a wide-ranging chat. Guest Tim Banks describes a systems career and discusses failure, community and unions. Speakers also give opinions on AI and the tech industry. The evidence is spoken opinion and anecdote.

Taming the Unpredictable: Reliability in Chaos

Michelle Brush, Google Inc.. 24 March 2026. Conference talk page, abstract only.

The page is short. It holds an abstract, a speaker biography and a link to a video. The abstract names four strategies for coping with unpredictable systems. The talk itself is not described beyond that.

What are skiplists good for?

Will Wilson, Co-founder & CEO, Antithesis. 16 April 2026. Company blog post, with one engineering anecdote.

The post explains skiplists briefly. It then tells how Antithesis built a skiptree for BigQuery. Its evidence is the author's own account of one production system. It gives table layouts but no benchmarks beyond a cost remark.

Should I run plain Docker Compose in production in 2026?

Posted by pmig, with replies from many commenters. 30 April 2026. Hacker News discussion thread about a company blog post.

A Hacker News thread with 413 points about a Distr post. The poster says Distr helps companies distribute software to customers. Commenters quote the post, then argue about alternatives such as Podman, Kubernetes and Swarm. Evidence is personal experience.

We put Bun's Rust rewrite in production on Prisma Compute

Alexey Orlenko, senior engineer at Prisma. 11 June 2026. Company engineering blog post, with test results.

The post is a company report on a runtime choice. It compares stable Bun and a canary build. The two failures are memory growth and a stuck database pool. Its evidence is Prisma's own testing plus one public bug report.

protobuf-py: Protobuf for Python, without compromises

Team Buf, Buf Technologies, Inc.. July 7, 2026. Company launch post for an open source library, with one benchmark.

Buf says protobuf-py is complete, readable and as fast as Google's C engine in production. The post explains why Google's Python package feels awkward. Its evidence is a conformance claim and a single end-to-end benchmark table.

Things I want in a modern relational query language

cb (posting on the sporks space community blog). 19 August 2026. Personal blog post, a design wish list with invented pseudocode.

The post is a wish list, not a proposal with a working tool. It draws on the author's experience with MySQL and Db2. Its examples use made-up syntax with sum types and pattern matching. Reader comments point to existing projects with similar aims.

The Twelve-Factor App (2025)

Posted by jxmorris12, with replies from many commenters. 27 August 2026. Hacker News discussion thread about a methodology page.

A Hacker News thread with 317 points about the twelve-factor page. Replies drift to multi-factor logins, Heroku nostalgia and what the factors replaced. The longest argument is whether config and secrets belong in environment variables. Evidence is mostly experience and argument.

Distributed Systems Classics (2017)

Posted by grep_it, with replies from many commenters. 14 September 2026. Hacker News discussion thread about a reading list.

A Hacker News thread with 351 points about Nicolae Vartolomei's list of ten papers. Commenters add favourites and argue about CAP, event ordering and physics. Evidence is expert opinion and anecdote.

A Distributed Systems Reading List

Not stated. Undated. Annotated reading list of links.

The page is a reading list, not an argument. It groups links into thirteen topics. These include latency, Google, consistency, Paxos, gossip and peer-to-peer. Many entries carry a one-line note. The list suggests a reading order for the Paxos papers.

Surprising Economics of Load-Balanced Systems

Marc Brooker, an Amazon Web Services engineer. Undated. Personal blog post using queueing theory and a simulation.

Marc Brooker poses a puzzle about servers behind a load balancer. Brooker answers with the Erlang C formula and a Monte Carlo simulation. The post concludes that larger systems get better latency at the same utilization.

The power of two random choices

Marc Brooker, an Amazon Web Services engineer. Undated. Personal blog post, with one small simulation.

Marc Brooker explains why load balancers using cached load data cause herding. Brooker then simulates four host-picking rules. Best of two random choices leads the others for refresh intervals from 10 to 70.

Root Cause Analysis? You're Doing It Wrong

kqr, on the Entropic Thoughts blog. Undated. Personal blog draft, marked by the author as an unedited early draft.

kqr argues that root cause analysis reduces a complex accident to one convenient cause. The draft outlines the CAST method from Leveson's handbook. It works one software outage through the method. The author warns that the draft is rough and points to better articles.

Glossary

Apple Silicon
Apple's own ARM-based processors used in recent Macs.
Arithmetic coding
A method that turns probabilities into a compact stream of bits.
AS 400
An older IBM business computer system.
AWS
Amazon Web Services, Amazon's cloud computing platform.
AXD301
An Ericsson ATM switch with a very large Erlang code base.
Background task
A periodic or event-triggered job inside Nexus that reports status.
Backpressure
Signals that tell a sender to slow down when a receiver is overloaded.
Best of two
Pick two servers at random, then send the request to the less busy one.
Betterproto
A Python Protobuf library that supports only proto3.
BigQuery
Google's cloud database built for scanning very large tables.
Brazilian jiu-jitsu
A grappling martial art with ranked belts.
Bun
A JavaScript and TypeScript runtime, an alternative to Node.js.
Byzantine fault
A failure in which a machine sends wrong or conflicting information.
Cache
Saved files, such as dependencies, reused to speed up later runs.
Calgary corpus
A set of 14 files long used to benchmark compressors.
Canary build
An early test release that is built from the newest code.
CAP theorem
A result about the trade-off between consistency and availability during a network split.
CAST
Causal Analysis based on Systems Theory, a method for investigating accidents.
Chain replication
A way to copy data through a line of servers.
CI
Continuous integration, the automated build and test runs triggered by code changes.
Circuit breaker
Code that stops retrying a failing call so the failure cannot spread.
CockroachDB
A distributed database that provides strong consistency.
Codemagic
A cloud service that builds and publishes apps, including for Apple platforms.
Conformance suite
A set of tests that checks a library follows the specification.
Connection pool
A set of open database connections that a program reuses.
Container
A packaged app plus its dependencies, run in isolation on a shared operating system.
Control plane
The software that manages and configures a larger system.
CRDT
A data type that merges edits from different machines without conflicts.
CRE
Customer Reliability Engineering, a Google team helping cloud customers run reliable services.
Deterministic
Giving the same results and calls whenever it is run with the same inputs.
DevOps
A way of working that joins software development and IT operations.
Dirty function
The thesis's term for a function that sends messages or calls certain risky built-ins.
DNS
The system that turns names into network addresses.
Docker Compose
A tool that starts several containers from one YAML file.
Domain
A user-defined data type with its own rules, as in the relational model.
Dotenv
A tool that loads settings from a .env file into the environment.
Durable execution
Saving a program's progress so it can resume after a crash.
EBS
Block storage volumes that attach to EC2 servers.
EC2
AWS service for renting virtual servers.
Embedding
A list of numbers that stands for the meaning of a piece of text.
Entropy
A measure of the average information in each symbol of a source.
Environment variable
A named setting that a program receives from its surroundings.
Erlang
A programming language built at Ericsson for telephone systems.
Erlang C formula
A formula giving the chance an arriving request has to wait in the queue.
Error budget
The amount of failure a service may have while still meeting its SLO.
ETTO principle
The idea that people trade thoroughness against efficiency in their work.
Event storming
A workshop method for mapping a business process as events.
Event-driven architecture
A design where services communicate by publishing and reacting to events.
Eventual consistency
A guarantee that replicas agree if updates stop, after some unspecified time.
Fault tolerance
The ability of a system to keep working despite errors.
Feature flag
A switch that turns a code path on or off without a new deploy.
Feedback loop
A path by which results are passed back so that corrections can be made.
Firecracker VM
A lightweight virtual machine used to isolate each job.
Flutter
A toolkit for building apps for many platforms from one code base.
Foreign key
A column that points at a row in another table.
Fork Around and Find Out
The name of the podcast, a play on a common saying.
Fuzzer
A tool that tests software with many random or varied inputs.
Generic mitigation
A fix that reduces harm from many kinds of failure, without needing the cause.
GitHub Actions
GitHub's built-in system for running automated workflows.
Gossip protocol
A method where nodes pass information to random peers, like spreading a rumor.
Hall sensor
A part that detects a magnet, used to sense when a laptop lid closes.
Hallway track
The informal conversations between sessions at a conference.
Hazard
A system state that makes an accident possible but does not guarantee one.
Headless
Running a computer without a screen, keyboard or mouse attached.
Herd behavior
Many clients acting on the same old information and piling onto one server.
Heroku
A cloud platform whose founders wrote the twelve factors.
Hibernate
A Java ORM library.
Hindsight bias
The habit of seeing past events as more predictable than they were.
Horizontal scalability
Handling more load by adding machines rather than a bigger machine.
IAM
AWS system for controlling who can do what.
Incident
An unplanned failure or outage in a software system.
Incident review
A meeting held after an outage to discuss what happened.
JVM
The Java Virtual Machine, which runs compiled Java bytecode.
Kafka
A widely used platform for streaming events between systems.
Kolmogorov complexity
The length of the shortest program that produces a given string.
Kubernetes
A system for running containers across many machines.
Lambda
AWS service that runs code without managing servers.
Load balancer
A component that spreads incoming requests across several servers.
Local optimization
Improving one team's step in a way that may hurt the whole flow.
Lossless compression
Compression after which the original data can be restored exactly.
Lossy compression
Compression that throws away detail people are unlikely to notice.
LZ77
A scheme that replaces repeated strings with pointers to earlier copies.
M/M/c queue
A queueing model with random arrivals, random service times and c servers.
MFA
Multi-factor authentication, which asks for more than a password.
Microservices
A design that splits an application into small services talking over a network.
Migration
A change to a database schema that must be applied to existing data.
MinIO
A self-hosted object store that speaks the S3 protocol.
Monitoring system
Software that watches servers and raises alarms when something fails.
Monte Carlo simulation
A method that estimates results by running many random trials.
Nexus
The core component of the Oxide control plane.
Nftables
The newer Linux packet filtering framework.
NoMachine
Software for controlling a computer's desktop over a network.
Nondeterministic
Not always giving the same result from the same input.
NoSQL
A family of databases that do not use the relational table model.
Omdb
The Omicron debugger, a command-line tool for inspecting the control plane.
OpenTelemetry
An open standard for collecting traces and metrics from software.
Orchestrator
A server that runs workflow code and dispatches steps to workers.
ORM
An object-relational mapper, a library that maps database rows to program objects.
Orphan container
A container still running after its service was removed from the Compose file.
OTP
The Open Telecom Platform, the library set that ships with Erlang.
Partial failure
A fault where some parts of a system work while others do not.
Partial order
An ordering in which some pairs of events have no defined order.
Pattern matching
Choosing code or rows by the shape of a value.
Paxos
A family of algorithms for getting nodes to agree on a value.
Percentile
The value below which a given share of measurements fall.
Percentile latency
The time below which a given share of requests finish, such as p99.
Podman
A container tool that runs without a central background daemon.
Point lookup
Fetching one row directly by its ID.
Postgres
An open-source relational database.
Projection
Choosing only some columns of a table in a query.
Protobuf

Protocol Buffers
A format and toolset for defining and serializing structured data across languages.
Proxy
A server that forwards requests on behalf of another.
Quadlet
A Podman feature that turns container files into systemd services.
Query planner
The database part that decides how to run a query.
Quorum
The number of nodes that must respond for a read or write to count.
Raft

RAG

RAII
A Rust and C++ pattern that frees resources when an object goes out of scope.
RDBMS
A relational database management system, such as MySQL or Postgres.

The ability to recreate a problem so it can be studied.

Tracing an incident back to one underlying cause and fixing it.
Rote memorization
Learning steps by heart without knowing why they work.
RSS

S3
AWS service for storing files as objects.
Savings Plans
A pricing option that trades a spending commitment for discounts.

Schema registry

Secrets store
A service that keeps passwords and keys apart from code.
Semantic search
Search that matches meaning, not just the words typed.
Skiplist
A randomized sorted list with extra express lanes that make search fast.
SLO
Service level objective, a target for how well a service should perform.
SQL
The long-standing language for querying relational databases.
SQLAlchemy
A Python ORM and SQL toolkit.
SRE

SREcon
A USENIX conference for site reliability engineers.
Stale data
Information that was correct when collected but may have changed since.
Stored procedure
Code saved and run inside the database itself.
Sum type
A type whose values are exactly one of several named variants.
Supervisor

Sysadmin

Systemd

Tech lead

Temporal

Throughput

Twelve-factor app

V8

Value stream
The path work takes from a request to delivery to a customer.
Vector clock

Vector database
A database that finds stored vectors closest to a query vector.
Vibe coding
Building software by prompting an AI model without careful review.
WebAssembly

Wide event
An event that carries most or all of an entity's data.
