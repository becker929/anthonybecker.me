File-based agent memory

Ten sources on keeping a coding agent's knowledge in plain files.

Written by Claude Opus 5.510 November 2026, 01:17 UTC (17:17 Pacific)

File-based agent memory stores what a coding agent learns in ordinary text files. This page lists six sources on it, oldest first. Each has its own page, which links to the original.

Themes here: What lasts (9), Saying it exactly (1), Handing over control (1), Small means (1), Given away (1).

Prompts are code, .json/.md files are state

Mario Zechner. 2025-06-02. Personal blog post with one worked example from the author's own project.

Mario Zechner argues for treating an LLM as an unreliable computer. The prompt is the program, and files on disk hold the state. The evidence is one real porting job on the Spine runtimes. The time saving is self-reported.

Layers of Memory, Layers of Compression

Tim Kellogg. 15 June 2025. Blog post, largely AI-written by the author's account.

Compares Letta's layered memory with Anthropic's multi-agent research system and Cognition's single-agent advice. It is included for its frame, because Letta's archive is often a vector database. Kellogg says the text is largely AI-written.

Advanced Context Engineering for Coding Agents

Dex Horthy, HumanLayer. 29 August 2025. Company blog post, based on a talk.

Describes a workflow called frequent intentional compaction. Research, plan and status files carry state between fresh contexts. It covers working context more than long-term memory. The evidence is worked examples, and HumanLayer sells tools in this area.

Claude Skills are awesome, maybe a bigger deal than MCP

Simon Willison. 16 October 2025. Personal blog post, with one hands-on trial.

Willison describes Anthropic's new Skills feature on the day of its launch. The post explains how skills load only when needed and compares them with MCP. Its evidence is one trial of a published skill and the author's own experience.

Show HN: Recall

Posted by mateenah, with replies from many commenters. 21 June 2026. Hacker News thread.

A thread of about 85 comments on a local project memory tool. Commenters describe their own practices and question whether such tools are needed. This is the only source here made of personal reports.

Agent memory as a file format

Cal Paterson. August 2026. Personal blog post, with a spec and tools.

Proposes memoryfield, an open format of Markdown pages with an optional SQLite vector index. It argues that memory should be data rather than a process. The case is design reasoning, from the format's author, with no benchmark results.

I accidentally turned LLM memory into program analysis

Posted by matt_d, with replies from many commenters. 28 August 2026. Hacker News discussion thread.

The thread discusses a pwning.systems post about Lemmalog, a Datalog agent memory. Commenters describe it as aimed at vulnerability research. They share their own memory setups and raise older symbolic AI ideas. The evidence is anecdote and opinion.

Just-In-Time Agent Memory with Runtime Agentic Research

Bingyu Yan and five co-authors, Beijing Academy of Artificial Intelligence. 28 September 2026. arXiv preprint with benchmarks and a new training dataset.

The paper proposes JAM, which stores full histories as files in a folder tree. A trained Researcher model then searches them for each request. The evidence is benchmark tables, ablations and timing from the authors' own system. Code is released.

Agents Don't Need Memory. They Need Documentation.

Kevin Liao. 3 October 2026, updated 5 October. Personal blog post, introducing the author's tool.

Argues that agents should read and maintain documents rather than use memory plugins. It introduces the author's own tool, Operator Memory. Its figures are illustrations, not measurements.

The components of agent memory

Lance Martin, Anthropic. 6 November 2026. Company engineering article.

Describes memory notes, wikis, injected context and an offline pass called dreaming. It reports evaluations of each. It has the most numbers of the six. They come from Anthropic testing its own models.

Glossary

Ahead-of-Time memory
Memory that is summarized or organized before any request arrives.
Answer set programming
A logic approach that can retract conclusions when new facts arrive.
BM25
A classic keyword-matching formula for ranking documents.
Claude Skills
Anthropic's feature of folders with instructions and scripts that Claude loads when relevant.
CodeQL
A tool that turns code into a queryable database for finding bugs.
Compaction
Replacing a long session history with a shorter written summary.
Context window
The text a model can see at once.
Cyc
A decades-old project to hand-encode common-sense knowledge as logic.
Datalog
A small declarative logic language that derives new facts from facts and rules.
Dreaming
An offline pass that reviews transcripts and notes, then corrects them.
F1
A score combining how many right answers were found and how few wrong ones.
Frontmatter
A small block of fields at the top of a Markdown file.
Frontmatter YAML
A short block of labeled metadata at the top of a Markdown file.
Graph RAG
Retrieval for LLMs that searches a graph of linked facts.
GRPO
A reinforcement learning method that scores groups of sampled attempts against each other.
Injected context
Text loaded into every session at the start.
Jq
A command-line tool for reading and editing JSON files.
Just-In-Time memory
Memory that is searched and assembled when a request arrives.
MCP
Model Context Protocol, a standard for connecting models to outside tools and data.
Prompt injection
An attack where text in the model's input tricks it into unwanted actions.
Provenance
A record of where a fact came from and how it was derived.
RAG
Retrieval-augmented generation: finding stored text and adding it to a prompt.
Sandbox
A restricted environment that limits what code running inside it can damage.
Semantic search
Finding text by meaning, using numeric embeddings of that text.
SFT
Supervised fine-tuning, which trains a model on worked examples.
Spine runtimes
Libraries in many languages that play 2D skeletal animations made in Spine.
Token
A small chunk of text that a model reads or writes.
Vector index
A store of those embeddings, built for fast lookup.
