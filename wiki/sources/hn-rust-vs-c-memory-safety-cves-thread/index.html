What it is

This is a thread under a link to Kobzol's blog post, dated 15 June 2026. The post argues that raw CVE counts mislead when comparing Rust with C and C++. Commenters add disagreement, corrections and side debates.

What it says

  • Commenter afdbcreid says Rust libraries file CVEs for UB that C++ libraries ignore. Commenter fweimer doubts this.
  • Commenter chilljinx says Rust UB can arise without unsafe, for example through dependencies.
  • Commenter jurschreuder says only 1% of vulnerabilities are memory related. Commenter khuey cites Google's 75% of exploited zero days.
  • Commenters argue over whether curl_getenv should assert on NULL or whether that is boilerplate.
  • A side thread debates modern C++. Commenter josephg cites a 1000x drop in Android memory safety vulnerability density.
  • Another side thread disputes whether Rust trades memory safety for supply chain risk.
  • Commenters dispute whether compliance makes CVE counts matter. Commenter john_strinlai calls them useless.

What evidence it gives

The thread offers argument, personal experience and links. Some commenters cite figures. Others challenge those figures or ask for sources. No commenter runs a new measurement.

Interests and limits

Commenters are self-selected and often argue from loyalty to a language. Figures such as 1% and 75% are stated without agreed sources. This is a record of a debate, not a finding. Deeper replies in the last part were only skimmed. Read status: partial, the first two thirds in full, the rest skimmed.
