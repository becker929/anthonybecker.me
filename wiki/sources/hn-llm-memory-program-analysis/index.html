File-based agent memory

What it is

matt_d submitted the post, and commenters replied. The article itself is not in the source text. Commenters describe it as storing facts with provenance and retractions in Datalog. The thread is the source here, not the post.

What it says

  • Several commenters report the same failure: the model keeps using conclusions that were already disproved.
  • Commenters suggest decision logs, provenance metadata and answer set programming as fixes.
  • Commenter sim04ful argues the LLM belongs only at the request and answer ends.
  • Some commenters compare the idea to CodeQL, Graph RAG, Cyc and earlier symbolic AI.
  • Commenters describe simpler setups. Examples are a SQLite text index and a one-fact-per-line Markdown file.
  • Some doubt it helps beyond grounding, and others note that LLM-built structures can drift.

What evidence it gives

The thread offers personal anecdotes, links to tools and papers, and argument. One commenter pastes a project plan graph as an example. No commenter reports a controlled test of the approach.

Interests and limits

Commenters are self-selected and mostly unverified. Many describe their own projects, and some link tools they wrote. Claims are not checked. The linked article was not read, so this page describes the thread only. Each claim is a commenter's view.

Connections

These links are this wiki's own reading, not claims the sources make.

  • Bloom Filters. Commenters report models that keep using conclusions already disproved. A standard Bloom filter has a similar difficulty: items cannot be deleted. Counting variants allow it, but give up the promise of no false negatives. Forgetting may be the expensive operation in any memory.
