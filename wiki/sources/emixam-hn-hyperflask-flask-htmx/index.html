What it is

emixam posted the home page of Hyperflask and joined the discussion. The thread had 364 points when saved. Commenters reacted to the framework and its design choices.

What it says

  • The author, emixam, presents Hyperflask as a Flask and htmx framework. It is a one-person project.
  • Many commenters debate Flask against FastAPI, with some praising Flask's stability and others wanting async.
  • Some commenters say it has too many abstractions to be plain Flask and htmx.
  • One commenter calls htmx a dead end because state lives in the URL. Others disagree.
  • A commenter argues for keeping UI state on the server. Critics raise latency and cost.
  • Commenters question putting the template in the controller file. The author cites locality of behavior.
  • Others suggest alternatives such as Litestar, FastHTML and Plain, and miss the Django admin.

What evidence it gives

The thread offers opinions, experience reports and links. One commenter describes a demo site that keeps UI state in a database. Another gives a worked SQLAlchemy example in a side argument about ORMs. None of it is a controlled test.

Interests and limits

The author of the framework answers criticism in the thread, so it is not neutral. Commenters are self-selected and often disagree. The hyperflask.dev site itself was not read for this page.
