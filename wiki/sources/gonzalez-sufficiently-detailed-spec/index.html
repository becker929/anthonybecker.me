What it is

Gabriella Gonzalez argues against generating software purely from specification documents. The post names two misconceptions. One is that specs are simpler than code. The other is that spec writing must be more thoughtful than coding.

What it says

  • The post reads OpenAI's Symphony spec as Markdown pseudocode, including schema dumps and outright code.
  • A spec precise enough to generate code reliably must come to resemble code.
  • It cites Dijkstra on narrow interfaces and the failure of verbal precision in mathematics.
  • It cites Borges's map as large as its empire, for a spec that keeps growing.
  • Specs were never time-saving devices, the post concludes.

What evidence it gives

Gonzalez asked Claude Code to build Symphony in Haskell from the spec. The result had several bugs. Even once it ran, the agent spun without progress on a trivial ticket. The post also notes that most YAML implementations fail to conform fully.

Interests and limits

This is one attempt, in Haskell rather than a mainstream language. The post addresses that objection. Calling the spec AI-written is the author's inference from its style. The argument targets specs used to replace code, not checks used to test it.
