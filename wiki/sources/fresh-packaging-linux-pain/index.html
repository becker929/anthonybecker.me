What it is

The post comes from the Fresh editor's own documentation blog. The author is not named on the page. It explains why the project now favors a static binary that updates itself.

What it says

  • The author says Windows and macOS are not so bad, Linux differs.
  • The project ships through many channels, such as cargo, AppImage, deb, rpm, AUR and nix.
  • Flatpak sandboxing fits poorly, the author says, because Fresh is a terminal program.
  • AppImage starts slowly because of a squashfs FUSE mount, the author says.
  • Debian packaging needs every Rust dependency packaged separately, which the author calls much work.
  • The mise install broke after GitHub rotated a certificate and mise kept an old root.
  • The planned main Linux channel is a static musl binary that updates itself.

What evidence it gives

The post gives first-hand anecdotes from one project. It names specific failures, such as the mise certificate problem and AUR being read-only. It gives rough sizes, about 12MB to download and 35MB extracted. It offers no survey or wider data.

Interests and limits

The author is not named and the post is undated. It speaks for one terminal editor, written in Rust. The static binary plan was untested when written. The author admits it may bring surprises. The post is on the project's own site.
