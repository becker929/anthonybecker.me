What it is

Lorin Hochstein writes a blog on software, complex systems and incidents. The post explains a result from Herlihy and Wing's linearizability paper and Lamport's book. The author says explaining is the best way to learn.

What it says

  • Hochstein describes a spec as a state machine: initial states plus allowed transitions.
  • A data structure is linearizable if each operation appears to take effect instantly.
  • To show an implementation meets a spec, map its states onto the spec's states.
  • Herlihy and Wing's array queue admits no such mapping, though it is linearizable.
  • Adding a prophecy variable that predicts dequeue order lets the mapping exist.
  • Wrong predictions only block dequeues or cause deadlock, which stays a valid behavior.

What evidence it gives

The post works through counter, queue, locked-list and array-queue examples with diagrams. It shows excerpts of PlusCal, Python and C++ code. Full TLA+ models are in two linked GitHub repositories. The post does not report running the models.

Interests and limits

The post is a personal explainer. The author says readers may not absorb it at first. The full prophecy mapping is deferred to Lamport's book. The post leaves liveness out. Model checking results are not reported. The figures were images, which were not viewed.
