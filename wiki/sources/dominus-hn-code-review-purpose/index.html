What it is

The linked post is by mjd, dated 26 August 2025. It claims review exists to find hard-to-maintain code, not bugs. The thread collects replies from many commenters, including one signed mjd.

What it says

  • The linked post says code review mainly exists to find hard-to-maintain code.
  • The post says relying on code review to find bugs is a fool's paradise.
  • Commenters such as thayne say code review has several purposes, including learning.
  • Commenter jibal calls the post's claim that bugs cannot generally be found by reading false.
  • A commenter named mjd says not all bugs, nor any given bug, can be found.
  • Commenter jerf notes that people agree code review is good but disagree on its point.
  • Commenter nunez says AI-made diffs are often gigantic, which defeats human reviewers.

What evidence it gives

The Mastodon post offers argument only. The thread is workplace anecdote, with a few mentions of compliance rules. No commenter cites a study.

Interests and limits

The linked post is short and was written ten months before the thread. Commenters are self-selected programmers. Practices differ between small teams, large firms and regulated work. Some comments treat the post as a flat rule when it may be a provocation.
