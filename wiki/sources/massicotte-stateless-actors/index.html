What it is

Matt Massicotte, who offers Swift concurrency consulting, answers a reader's question about stateless actors. The post covers network clients, background actors, custom executors and file system access.

What it says

  • Massicotte first thought an actor with nothing to isolate seemed a strange thing.
  • A stateless network client actor is Sendable and keeps JSON decoding off the main thread.
  • Actors run work serially, so a client actor decodes one JSON response at a time.
  • A custom background actor also runs work serially and can spread through the type system.
  • Actors that adapt Swift concurrency to an existing queue system through custom executors are important.
  • An actor guarding the file system can make sense, as the compiler cannot see it.
  • The post concludes a stateless actor is strange but can make sense with purpose.

What evidence it gives

The post gives short Swift code samples and reasoning about how actors behave. It reports no benchmarks and no tests.

Interests and limits

The post is the author's opinion and experience. Massicotte offers paid help with Swift concurrency, and says so at the end. Nothing was measured. The advice applies to Swift's actor model only.
