Reverse engineering GitHub Actions cache to make it fast

A company engineer explains how Blacksmith redirects GitHub Actions cache traffic.

Author
Aaditya Sondhi, Founding Engineer, Blacksmith

Subject

What it is

Aaditya Sondhi describes how Blacksmith sends job cache requests to its own cache. Customers change no workflow files.

What it says

  • Sondhi says Blacksmith reroutes Actions cache requests to its own cache.
  • The post says maintaining forked cache actions became too costly.
  • Sondhi says an LLM helped derive a proto definition from captured requests.
  • The post says each VM's NGINX proxy forwards cache requests to a host proxy.
  • Sondhi says the toolkit skips optimizations for non-Azure hostnames, so Blacksmith built Azure-like URLs.
  • The post says iptables rules became flaky, so Blacksmith moved to nftables.
  • Sondhi claims up to 10x faster cache speeds, with one log showing 327.5 MBs/sec.

What evidence it gives

The post gives a technical walkthrough of the design. It shows one before-and-after log for a cache of about 114 MB. It gives no wider benchmark or method for the 10x figure.

Interests and limits

Blacksmith sells the service the post promotes, and the post includes sign-up links. The speed claim is "up to 10x" for some customers. Only one log sample is shown. No third party tested the result.
