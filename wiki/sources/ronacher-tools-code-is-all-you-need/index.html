What it is

Armin Ronacher is a software developer who writes a personal blog. The post explains why Ronacher dislikes the Model Context Protocol (MCP) as it works today. It argues that code generation composes better and uses context more efficiently. It ends with ideas for what might replace MCP.

What it says

  • Ronacher says MCP is not truly composable, because most composition happens through inference.
  • The post says MCP needs much upfront context. Each call costs more context than running code.
  • Ronacher says code suits repeated tasks, because people can review a formula, not results.
  • Ronacher converted a blog to Markdown. An LLM wrote conversion, diff and analysis scripts, then looped.
  • The post says that loop's cost tracks iterations and sample size, not document count.
  • The post says a generated Playwright script can run 100 to 300 times without inference.
  • Ronacher muses that better sandboxes and APIs could let agents fan out inference.

What evidence it gives

The evidence is one detailed anecdote, the blog conversion, plus a Playwright example. The post suggests readers try one GitHub task with the MCP, then with gh. It reports no measurements, token counts or benchmarks.

Interests and limits

This is one developer's experience, mostly in agentic coding. Critics say MCP may suit end-user apps. The post answers with argument, not a test. The author does not report a test of the future tool-filtering approaches. Results from one blog conversion may not carry over to other tasks. The author says the Playwright approach works only where the page is already known.
