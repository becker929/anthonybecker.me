What it is

Dex Horthy's post describes a workflow for coding agents in large existing codebases. The post calls it frequent intentional compaction. Files carry state between fresh contexts, which is why it appears here. The post is about working context more than long-term memory.

What it says

  • Compaction distils search results, logs and tool output into structured artifacts.
  • Work moves through research, plan and implement steps.
  • On complex work, status goes back into the plan file after each verified phase.
  • Context use should stay between 40% and 60%, depending on the problem.
  • Subagents are for context control. They search in a fresh window and return a summary.
  • Human review should focus on research and plans. One error there can cause thousands of bad lines.

What evidence it gives

The evidence is worked examples rather than controlled tests. Horthy reports a bug fix in BAML, a 300k-line Rust codebase, approved by its maintainer. Horthy and a collaborator then shipped 35k lines in seven hours. The collaborator estimated each resulting PR at three to five days of senior work. Horthy also reports a seven-hour attempt on parquet-java that did not go well.

Interests and limits
