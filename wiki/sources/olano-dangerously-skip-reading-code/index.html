What it is

Facundo Olano is a programmer who blogs on olano.dev. This post follows an earlier one. That one called it irresponsible to assume LLMs will fix every problem. This one asks what changes if an organization mandates minimal time spent coding.

What it says

  • Programmers are accountable for understanding code, a proxy for understanding the system.
  • If leadership accepts the risks, the author says LLM code could go unread, like assembly.
  • The author says this must be an organizational decision, citing Amdahl's law.
  • The post says teams would need fewer approval steps, since rework is almost free.
  • The author bets rigor moves to specs and tests, led by a Markdown spec.
  • The post proposes automated pull-request checks that verify code conforms to the spec.

What evidence it gives

The post offers argument only. It cites a Thoughtworks retreat report as the point where the idea clicked. It gives no data, code or case study.

Interests and limits

This is a personal opinion post, short and conditional. It describes a process the author says they would try, not one that was run. The post does not say what happens when the spec and the code disagree. Its reach is limited to organizations that have chosen this trade-off.
