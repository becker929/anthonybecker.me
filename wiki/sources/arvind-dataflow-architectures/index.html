What it is

Arvind and David Culler wrote this memo at MIT, for a 1986 annual review. It sets out to describe dataflow graphs as a parallel machine language and compare designs.

What it says

  • Dataflow graphs are described as a machine language for parallel machines.
  • Static dataflow allows one token per arc, while dynamic dataflow tags tokens and pools them.
  • Enforcing one token per arc reduces the parallelism a program can exploit.
  • The paper cites earlier work showing no interpreter offers more parallelism than tagged-token.
  • I-structures are slots that can be written at most once, with early reads deferred.
  • The survey covers major static and tagged-token dataflow projects and gives a prognosis.
  • The authors call dataflow an extreme answer to memory latency, as the processor never waits.
  • The prognosis is hedged: dataflow machines are likely competitive, but not claimed lightly.

What evidence it gives

The memo offers argument, worked examples and descriptions of real machines. It cites earlier papers and reports some hardware figures taken from those projects. It runs no new experiments.

Interests and limits

The text came from a noisy scan, and the figures were not viewed. The MIT server refused the PDF, so the text comes from an archived copy. The authors belong to the MIT group behind the tagged-token machine. The 1986 prognosis predates later hardware. The catalog page lists the date wrongly. The paper warns tagged-token machines can deadlock, so the authors bound parallelism.
