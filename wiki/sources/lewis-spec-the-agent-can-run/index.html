What it is

Adam Lewis argues that what matters in a spec is whether it can be executed. The format and length barely matter by comparison. The post belongs to a collection of software-craft tenets at prickles.org.

What it says

  • A table of contents that should work is intent. A checkable heading position is not.
  • A spec an agent invents mid-task sits inside the loop and grades itself generously.
  • A spec written beforehand, which the agent cannot edit, sits outside the loop.
  • One executable check that defines done can be enough.
  • Large specs stop being verifiable without anyone noticing, so short per-step checks work better.

What evidence it gives

The post offers one small example and reasoning from experience. It reports no measurements.

Interests and limits

It is a short opinion post, and it promotes the author's wider collection of tenets. It does not discuss criteria that resist automation. It does admit that fuzzy tasks are hard.
