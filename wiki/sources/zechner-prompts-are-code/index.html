What it is

Mario Zechner is a developer who maintains the Spine runtimes. The post sets out the mental model first. It then walks through a prompt file that ports Java changes to other languages.

What it says

  • Zechner says coding agents struggle on big codebases. Causes include missing context, weak execution-flow tracking and lack of taste.
  • The post says things fall apart around 100k tokens, regardless of benchmark claims.
  • Zechner proposes a mapping. The prompt is the program, and tool calls and user input are I/O.
  • State is serialized to disk, as JSON or Markdown. Work can then resume with fresh context.
  • The example is a port.md prompt. A script pre-generates a JSON plan of changed Java types.
  • Zechner reports that work which took 2-3 weeks now takes 2-3 days. Human checkpoints stay in the loop.

What evidence it gives

The evidence is one real project. The post shows the prompt file, the JSON state format and the jq queries. A video recording is described. The time saving is the author's own report with no measurement.

Interests and limits

Zechner maintains the codebase and designed the workflow, so the result is self-reported. Only one task and one coding tool were used. The post says the LLM cannot do the full port alone. It also says this is not a panacea. The long code listings and middle workflow steps were skimmed, not read in full.
