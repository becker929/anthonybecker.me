What it is

Simon Willison writes a long-running weblog on AI tools. The post shares patterns for running multiple coding agents and links to other practitioners.

What it says

  • The author moved from skepticism to regularly running several coding agents at once.
  • Review is the bottleneck, so parallel tasks must add little review load.
  • Research tasks, such as proof of concept builds and codebase questions, suit parallel agents.
  • Small maintenance jobs, such as fixing deprecation warnings, can be handed to a bot.
  • Code built from the author's own detailed specification is far easier to review.
  • The author runs agents without approvals when confident malicious instructions cannot reach the context.
  • Riskier tasks go to cloud-based asynchronous agents, so the worst case is leaked source code.

What evidence it gives

The evidence is the author's personal experience over a few weeks. The post gives no measurements or comparisons. It links to other practitioners' write-ups as further reading.

Interests and limits

The post reflects one developer, mostly on open source work. The author says the patterns are still settling and expects them to change. No claim about speed or quality was tested. The author notes local agents should run in containers, and has not yet done so.
