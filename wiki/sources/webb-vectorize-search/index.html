What it is

Matt Webb runs Braggoscope, an unofficial directory of BBC Radio 4 show In Our Time. The post is on the PartyKit blog. PartyKit had just added vector database support. It explains embeddings and then walks through five steps to a working search.

What it says

  • Webb says search has become much easier to build because of AI.
  • Webb explains that nearby embedding vectors mean roughly the same thing.
  • Indexing turns each episode description into a vector and upserts it into Vectorize.
  • A query is embedded, then the nearest stored vectors come back with their metadata.
  • The finished server is 162 lines, including boilerplate.
  • Webb adds that vector databases also underpin retrieval-augmented generation (RAG).

What evidence it gives

The post gives the full indexing and query code and a link to a repository. It shows one example query, "the biggest planet", returning a Jupiter episode. It offers no relevance measurements and no comparison with keyword search.

Interests and limits

The post is on the blog of PartyKit, which sells the platform it showcases. Search quality is shown with one example, so "unreasonably good" is the author's judgment. The linked repository, demo site and Braggoscope were not opened. The setup steps were not run.
