Finite State Machines in Forth

What it is

J.V. Noble, of a university physics institute, wrote this note for Forth programmers. It gives methods for deterministic and nondeterministic finite state automata. The stated goal is a one-to-one match between the definition and the state table.

What it says

  • Noble says nested IF logic is hard to read, debug or modify. It can also be slow.
  • The note replaces history flags with one state variable. A state table gives actions and transitions.
  • A brute-force version uses CASE: with one word per state. The note calls it inadequately factored.
  • The defining word FSM: compiles a table of execution tokens. State and input column index it.
  • The final form reads like the state table. Named transitions such as >1 follow each action.
  • Using a word, not a number, for each transition allows nondeterministic machines. No other redefinition is needed.

What evidence it gives

The note gives complete Forth definitions and short console tests for the number-entry example. It adds an identifier recognizer and floating-point recognizers. It cites no benchmarks, so the speed claims are argument only.

Interests and limits

Some code works only on indirect-threaded Forths, and an appendix gives alternatives. Some helper words are left as an exercise. The claim about speed was not measured.
