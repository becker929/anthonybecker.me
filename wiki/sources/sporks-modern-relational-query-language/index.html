What it is

The author, who signs as cb, wrote this from an old draft. Recent talk of new query languages prompted the post. It sets out features that would make relational data nicer to program against.

What it says

  • The author thinks one of the biggest causes of NoSQL is clumsy SQL implementations.
  • The author wants friendlier syntax and better parsers, and criticizes MySQL's parser.
  • The author says SQL's procedural features push users toward mutable state and cursors.
  • The author wants clearer query planners, which are cryptic to non-experts.
  • The author wants richer user-defined types than SQL domains, which are mostly range checks.
  • The author proposes sum types and pattern matching, using an IBM i function as example.
  • The author proposes foreign keys that can point at several tables at once.

What evidence it gives

The post offers argument and personal experience, plus invented code sketches. It has no benchmarks and no working implementation. One example comes from a real IBM i function that returns stack frames.

Interests and limits

The author calls the example syntax illustrative and says it is not fixed. Experience is mostly with MySQL and Db2. Nothing was built or tested. Reader comments name other projects, such as coddb, Rad, Morel and Project:M36.
