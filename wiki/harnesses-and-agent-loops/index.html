Harnesses and agent loops

37 sources on the software that surrounds a coding agent.

Written by Claude Opus 5.59 November 2026, 05:32 UTC (21:32 Pacific)

A harness is the software around a model that decides what happens next. A loop runs the agent again until something says stop. This page lists 37 sources, oldest first where dated. They range from a very short opinion post to a long research survey.

Themes here: Handing over control (23), Feedback loops (5), Checking the work (4), Skill under automation (4), Small means (4), Who holds the power (3), What lasts (2), Getting good (2), Art through code (2), How things break (2), Rules that generate (1), What counts as a mind (1), Saying it exactly (1), Given away (1).

Context engineering

Chris Loy. 3rd August 2025. Personal blog explainer with a worked toy example.

Chris Loy traces how prompting grew from text completion into context engineering. The post proposes design patterns for context, borrowed from software design. Its evidence is a toy example about film box office figures, not tests.

The quality of AI-assisted software depends on unit of work management

Atharva Raykar (nilenso). 15 September 2025. Company blog opinion post, with napkin arithmetic.

Atharva Raykar argues that context management and unit size matter more than raw model intelligence. The post uses a compounding-error calculation and a reading of the METR long-task study. It proposes user stories as the unit of work and announces an early experiment.

Embracing the parallel coding agent lifestyle

Simon Willison. 5th October 2025. Personal blog post from a working developer.

Willison explains how skepticism about parallel agents gave way to regular use. The post sorts suitable tasks into research, small maintenance and well-specified work. It also lists the author's tools and safety habits. The evidence is personal experience.

Vibe engineering

Simon Willison. 7th October 2025. Personal blog post proposing a term, with practitioner opinion.

Willison coins vibe engineering for skilled engineers who stay accountable for LLM-built work. The post lists practices that make agents work better. It argues these favor experienced engineers. It rests on personal experience and carries a later update on terminology.

Technical Deep Dive on Streaming AI Agent Desktop Sandboxes: When Gaming Protocols Meet Multi-User Access

Luke Marsden and Chris Sterry (HelixML). Oct 30, 2025. Company engineering blog post on a Substack, about work in progress.

Helix explains how it adapted the Moonlight game protocol for several users. The post covers a workaround called apps mode and a newer lobbies mode. It is a narrative of design choices and open bugs, with little measurement.

Windsurf Codemaps: Understand Code, Before You Vibe It

The Cognition Team (Cognition, maker of Windsurf and Devin). 4 November 2025. Company product announcement blog post.

A product announcement from Cognition, the company behind Windsurf and Devin. It pairs a feature description with an argument against AI that replaces understanding. The evidence is a feature walkthrough and outside estimates, not benchmarks.

A Software Engineer's Guide to Agentic Software Development

Brittany Ellich (GitHub engineer). 24 November 2025. Personal blog post, a how-to based on the author's own work.

A personal blog post by a GitHub engineer on clearing tech debt with coding agents. It describes a three-step routine and the limits on daily workload. The evidence is the author's own experience, with no measurements.

Effective harnesses for long-running agents

Justin Young, Anthropic. Nov 26, 2025. Company engineering blog post describing internal experiments.

Anthropic describes a two-part harness with an initializer agent and a coding agent. The test case is building a clone of claude.ai. The evidence is qualitative observation, with no benchmark numbers.

AI agents are starting to eat SaaS

Martin Alderson. December 15, 2025. Personal newsletter essay, opinion with anecdotes.

Alderson argues that agents make building in-house tools cheaper than buying SaaS. The post lists what it expects to resist this, such as payments and network-effect products. The evidence is the author's own experience and a few secondhand examples.

Vibe Coding

David Bau. 16 December 2025. Personal blog post with one worked project and reader comments.

A personal blog post about one project, a fractal viewer rewritten by Claude Code. It offers two rules for working with agents and a wary reflection on complexity. The evidence is one project with linked code and reader comments.

Digital Red Queen: Adversarial Program Evolution in Core War with LLMs

Sakana AI, in collaboration with MIT. January 08, 2026. Company research blog post summarizing a paper, with interactive visuals.

Sakana AI summarizes a self-play method called Digital Red Queen. Each new program is evolved to beat all earlier ones. The post reports growing robustness and convergent behavior. It states results in words, and points to a paper and code for details.

Kellogg maps the model's five systems onto two agents Kellogg runs, Strix and Lumen. The evidence is the author's own anecdotes and design choices. The post includes comments from Strix itself.

Harness engineering: leveraging Codex in an agent-first world

Ryan Lopopolo, Member of the Technical Staff, OpenAI. February 11, 2026. Company engineering blog post reporting one internal project.

Lopopolo reports that a small OpenAI team built a product with no hand-written code. It covers docs as a map, strict architecture rules, light merge gates and cleanup agents. The evidence is the team's own account and estimates.

The 8 Levels of Agentic Engineering

Bassim Eledath. 10 March 2026. Personal blog post, a practitioner framework from experience and conversations.

Bassim Eledath lays out eight levels, from tab complete to autonomous agent teams. The levels draw on talks with teams and the author's own tools. The post gives opinion and examples, not measurements.

The HumanLayer team argues that coding agent failures come from configuration, not the model. The evidence is team experience, one example hook script, and outside studies. The post gives concrete tips on each configuration point.

Simon Willison picks timestamped quotes from a talk at the Pragmatic Summit. Topics range from testing agents to prompt injection and open source. The evidence is the speaker's own practice, with links to related posts.

Structured CoT: Shorter Reasoning with a Grammar File

The post forces a Qwen3.6 model to write its think block in a fixed format. It reports results on HumanEval+ and on 50 recent LiveCodeBench problems. The evidence is two benchmark runs on one model, with limits listed by the author.

agents need control flow, not more prompts

brian. 07 May, 2026. Very short personal blog post, argument only.

The post is a brief thesis with no code or data. It claims prompt chains cannot be reasoned about, so logic belongs in the runtime. It adds that agents also need programmatic verification.

GLM-5.2 is the step change for open agents

Nathan Lambert says GLM-5.2 is the first open-weight model that feels right in coding harnesses. The post relies on community benchmarks, reactions from others and brief personal use. It also discusses market and policy effects.

Ronacher separates the agent loop from the harness loop that decides when work is done. The post draws on personal experience, a few outside examples and no measurements. It ends uneasy but expects loops to spread.

A Substack essay on how much harness an agent needs. It uses a two-axis framing, practitioner quotes and one case study. The evidence is cited examples and argument, with no experiments.

How much can you delegate to agents?

Yoon argues that trust in agents depends on the task, not on model quality. Two questions place any task on one of four levels. The examples come from PostHog's own engineering work, and the post has no measurements.

Introducing Kitesurf: The agent-first browser that runs in V8 isolates on Cloudflare Workers

Shankar argues that software businesses will move work from people to agent harnesses. The essay lays out a four-stage trajectory. It answers the objection that this makes low-quality output. It is argument only, with a few named examples of in-house tools.

Glossary

ACP
Agent Client Protocol, a standard for connecting editors to coding agents.
Agent delegation
Handing a task to an AI agent to carry out with limited supervision.
Agent loop
The cycle where a model calls a tool, reads the result and continues.
Agentic coding
Software work in which an AI agent writes and edits code with some autonomy.
Agentic engineering
Building software with coding agents that write and run code.
AGENTS.md
A file of standing instructions that a coding agent reads.
AGPLv3
A strong open-source license that requires sharing source for network services.
Algedonic signal
A pain or pleasure signal that goes straight to the top-level system.
Asynchronous
Working in the background without making other work wait.
Asynchronous agent
A cloud agent that works on a task in the background.
Attractor basin
A stable pattern that a system tends to fall back into.
Back-pressure
Checks such as tests that push back when the agent's work is wrong.
Background agent
An agent that works on a task without a person watching.
Backpressure
A check that pushes failure back into the next attempt.
Blast radius
How much could break if a change goes wrong.
Chain of thought
Text where a model writes out intermediate reasoning before its answer.
Change-point monitoring
Closely watching a system around releases and config pushes, when regressions are most likely.
Chesterton's Fence
The rule not to remove something until you know why it is there.
Chrome DevTools Protocol
The interface that tools like Puppeteer use to control a browser.
Clanker
The post's slang term for an AI system.
Cloudflare Worker
A small server program that runs on Cloudflare's network.
Code coverage
A measure of which lines of code the tests actually run.
Codebase
The full set of source code files for a software project.
Codex
OpenAI's coding agent.
Coding agent
An AI tool that writes, runs and fixes code on its own.
Compaction
Summarizing a long conversation so it fits the model's context window.
Context engineering
Choosing what information a model sees in each call.
Context window
The limited amount of text a model can consider at once.
Control flow
The order in which a program takes its steps, such as branches and loops.
Convergent evolution
Separate lineages arriving at similar traits independently.
Core War
A 1984 game in which programs fight for control of a shared virtual memory.
CRDT
A data structure that lets several editors change one document and merge cleanly.
CRUD
Basic create, read, update and delete operations on stored data.
Cybernetics
The study of control and feedback in machines, organisms and organizations.
DAG
A directed acyclic graph, here a task list with dependencies and no loops.
Deduplication
Merging reports that describe the same underlying bug.
Deskilling
Loss of a skill from lack of practice.
Deterministic
Giving the same result every time from the same input.
Episodic memory
Stored records of past runs, reused when a new task looks similar.
Evolutionary search
Improving candidates by mutating them and keeping the fittest.
Exfiltration
Sending private data out to an attacker.
False negative
A real bug that the system fails to report.
Feature flag
A switch that turns a software feature on or off without a new release.
FIFO queue
A line where the first item added is the first one handled.
Frontier model
One of the most capable and costly models available.
Fuzz testing
Feeding a program random inputs to find failures.
GBNF grammar
A rule file that limits which tokens a model may produce while it generates text.
Git bisect
A git command that finds the change that introduced a bug.
Git worktree
A separate checked-out copy of a repository sharing one history.
Guard type
A type that can only be built by passing a check.
Guardrail
A fixed check that blocks or redirects unwanted agent behavior.
Harbor
A framework for running and checking agent benchmarks.
Harness
The tools and runtime code around a model that let it act.
Harness engineering
Building the control code around a model, such as retries, state and monitoring.
Headless browser
A browser that runs without a visible window, for automation.
Hook
A script that runs automatically at set points in an agent's work.
HumanEval+
A set of Python coding problems with extra tests, possibly seen in training.
Hunter agent
An agent assigned to attack one class of bug in one area of code.
Hyrum's Law
The idea that someone will come to depend on every observable behavior of an interface.
In-context learning
A model picking up a task from examples placed in its prompt.
Inference
Running a trained model to produce answers.
Initializer agent

LangGraph

Linter
A tool that checks code against style or structure rules.

MCP
