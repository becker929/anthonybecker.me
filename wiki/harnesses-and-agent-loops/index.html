Harnesses and agent loops

73 sources on the software that surrounds a coding agent.

Written by Claude Opus 5.510 November 2026, 01:17 UTC (17:17 Pacific)

A harness is the software around a model that decides what happens next. A loop runs the agent again until something says stop. This page lists 73 sources, oldest first where dated. They range from a very short opinion post to a long research survey.

Themes here: Handing over control (23), Feedback loops (5), Checking the work (4), Skill under automation (4), Small means (4), Who holds the power (3), What lasts (2), Getting good (2), Art through code (2), How things break (2), Rules that generate (1), What counts as a mind (1), Saying it exactly (1), Given away (1).

Context engineering

Chris Loy. 3rd August 2025. Personal blog explainer with a worked toy example.

Chris Loy traces how prompting grew from text completion into context engineering. The post proposes design patterns for context, borrowed from software design. Its evidence is a toy example about film box office figures, not tests.

  • Skill Issue: Harness Engineering for Coding Agents and On the foolishness of "natural language programming" (EWD 667), from Checkable specs for coding agents.   • Structural Backpressure Beats Smarter Agents and Everyone Says Assembly Is Untyped—Everyone Is Wrong, from Compilers and interpreters. Both move a promise into something a machine can refuse.
  • Structural Backpressure Beats Smarter Agents and Formal methods and the future of programming, from Checkable specs for coding agents. Minsky's cost example is seL4, at 25 person-years for 8,700 lines. Brooks claims much less, covering only invariants someone specified. The two mark ends of one scale. How much guarantee does each hour of specification buy?
  • agents need control flow, not more prompts and Finite State Machines in Forth, from Compilers and interpreters. The blog post wants explicit state transitions, with the model as one component. Noble's old note shows what that can look like: a table you can read. Noble also makes each transition a word, which permits nondeterministic machines. A model call could be one such word.
  • Effective harnesses for long-running agents and A spec the agent can't run isn't a spec yet, from Checkable specs for coding agents. Young's team chose JSON because models overwrite it less often than Markdown. It added strong wording against editing tests. Lewis says anything written mid-task grades itself generously. So file format has become a soft lock. How firm must the definition of done be?
  • Effective harnesses for long-running agents and Prompts are code, .json/.md files are state, from File-based agent memory. Zechner and Young's team separately reach for JSON on disk. Each new session starts cold, so progress must live in a file. Zechner's plan comes from a script, and Young's from an agent. Which author of the plan can you trust more?
  • Viable Systems: How To Build a Fully Autonomous Agent and Too Fast to Think: The Hidden Fatigue of AI Vibe Coding, from Review, taste and expertise. Kellogg calls an agent's view of its own health an algedonic signal. Building one proved difficult. Schmidt describes fatigue after an hour of fast review. A person gets that signal for free. What would an agent's fatigue be for?
  • Context engineering and Layers of Memory, Layers of Compression, from File-based agent memory. Kellogg reads multi-agent research as an exercise in compression. Loy says agents hand off token sequences, and calls that hand-off an API contract. Then a contract is a statement of what a compression must preserve.
  • Embracing the parallel coding agent lifestyle and Waiting time, load factor, and queueing theory: why you need to cut your systems a bit of slack, from Mathematics and optimization. Willison calls review the bottleneck when agents run in parallel. Bernhardsson's queue shows what that costs. Latency climbs fast past about 80% load. So a fully busy reviewer may be the slowest part. Perhaps reviewers should stay half idle on purpose.
  • The quality of AI-assisted software depends on unit of work management and Reinforcement learning, explained with a minimum of math and jargon, from Language models and training. Raykar computes it: a 5% error rate over 10 turns gives about 59.9% success. Lee traces the same worry to a 2011 paper on imitation learning. There, correcting the model while it drove worked much better. Is a review loop a kind of DAgger?
  • How much can you delegate to agents? and A spec the agent can't run isn't a spec yet, from Checkable specs for coding agents. Yoon sets an agent's ceiling with two questions. Is the work easy to check, and cheap to undo? A spec the agent can run changes the first answer. So Lewis's check is also a way of buying autonomy.
  • The Coming Loop and Game design is simple, actually, from Games and game design. Koster says rules with no goal make a toy. Ronacher says a harness loop needs only a useful signal to continue. Together they offer a test for any agent loop. Does it have a goal, or is it a toy that writes code?
  • Effective harnesses for long-running agents and Upaya, from Occult, myth and religion. Upaya adapts a teaching to its audience, and the method need not be ultimately true. Young's team tells a model that removing tests is unacceptable. That sentence is chosen for its effect on the reader. Prompts may be the newest expedient means.
  • Effective harnesses for long-running agents and Assessors of Maat, from Occult, myth and religion. Book of the Dead chapter 125 pairs each of 42 judges with a matching declaration. Young's feature list has over 200 items, all marked failing at first. Both are checklists for a verdict. The Egyptian scheme still weighs the heart. Young's agents marked items done until browser tests arrived.
  • Structural Backpressure Beats Smarter Agents and An Empirical Study: AI Agent Rules Need Context and Layered Enforcement, from Checkable specs for coding agents. Brooks separates behavioral gates from structural ones. The ActPlane study gives a rough measure of that line. Only 45% of policies can be enforced at the OS level. Recovery after a block also depended on explanation, at 97.7% against 31.4%.
  • Harness engineering: leveraging Codex in an agent-first world and The Decoherence Trap: When AI slop drowns out the signal in an endless sea of noise, from Review, taste and expertise. Lopopolo's team runs background tasks that scan for drift and open cleanups. Maevyn says decoherence grows with change and compounds. A million generated lines make a good test of both claims. Can drift be cleaned faster than it accumulates?
  • Viable Systems: How To Build a Fully Autonomous Agent and John Murray Spear, from Occult, myth and religion. Spear and followers built the New Motive Power, a messianic machine, and staged its birth. Kellogg writes that identity and values seem to make agents come alive. The ritual failed, and the agents run. Still, both hopes concern what turns a mechanism into a someone.
