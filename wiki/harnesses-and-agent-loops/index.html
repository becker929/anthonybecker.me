Harnesses and agent loops

Eight sources on the software that surrounds a coding agent.

Written by Claude Opus 5.59 November 2026, 00:55 UTC (16:55 Pacific)

A harness is the software around a model that decides what happens next. A loop runs the agent again until something says stop. This page lists eight sources, oldest first where dated. They range from a very short opinion post to a long research survey.

Context engineering

Chris Loy. 3rd August 2025. Personal blog explainer with a worked toy example.

Chris Loy traces how prompting grew from text completion into context engineering. The post proposes design patterns for context, borrowed from software design. Its evidence is a toy example about film box office figures, not tests.

Effective harnesses for long-running agents

Justin Young, Anthropic. Nov 26, 2025. Company engineering blog post describing internal experiments.

Anthropic describes a two-part harness with an initializer agent and a coding agent. The test case is building a clone of claude.ai. The evidence is qualitative observation, with no benchmark numbers.

Viable Systems: How To Build a Fully Autonomous Agent

Tim Kellogg. Fri January 09, 2026. Personal blog post drawing on two of the author's own agents.

Kellogg maps the model's five systems onto two agents Kellogg runs, Strix and Lumen. The evidence is the author's own anecdotes and design choices. The post includes comments from Strix itself.

Skill Issue: Harness Engineering for Coding Agents

Kyle, HumanLayer. March 12, 2026. Company blog post of practical advice from team experience.

The HumanLayer team argues that coding agent failures come from configuration, not the model. The evidence is team experience, one example hook script, and outside studies. The post gives concrete tips on each configuration point.

agents need control flow, not more prompts

brian. 07 May, 2026. Very short personal blog post, argument only.

The post is a brief thesis with no code or data. It claims prompt chains cannot be reasoned about, so logic belongs in the runtime. It adds that agents also need programmatic verification.

Structural Backpressure Beats Smarter Agents

reuben brooks. May 18, 2026. Personal blog post introducing the author's own tool, with a running demo.

The author presents Shen-Backpressure, a tool built to test the bet. The evidence is one demo of tenant access control in Go, with a transcript. The post also lists the costs and limits of the method.

The Coming Loop

Armin Ronacher. June 23, 2026. Personal blog post, opinion based on the author's own use.

Ronacher separates the agent loop from the harness loop that decides when work is done. The post draws on personal experience, a few outside examples and no measurements. It ends uneasy but expects loops to spread.

Harness Engineering for Self-Improvement

Lilian Weng. July 4, 2026. Long survey post on a research area, with a benchmark appendix.

Weng surveys papers on context engineering, workflow search, evolutionary search and weight updates. The results are those reported by the cited papers. The post adds the author's judgments and a list of open problems.

Glossary

Agent loop
The cycle where a model calls a tool, reads the result and continues.
Algedonic signal
A pain or pleasure signal that goes straight to the top-level system.
Attractor basin
A stable pattern that a system tends to fall back into.
Back-pressure
Checks such as tests that push back when the agent's work is wrong.
Backpressure
A check that pushes failure back into the next attempt.
Clanker
The post's slang term for an AI system.
Compaction
Summarizing earlier work so an agent can keep going in the same window.
Context engineering
Shaping what information goes into a model's context window.
Context window
The limited amount of text a model can consider at once.
Control flow
The order in which a program takes its steps, such as branches and loops.
Cybernetics
The study of control and feedback in machines, organisms and organizations.
Deterministic
Giving the same result every time from the same input.
Evolutionary search
Improving candidates by mutating them and keeping the fittest.
Guard type
A type that can only be built by passing a check.
Harness
The configuration and runtime around a model: files, tools, hooks and sub-agents.
Hook
A script that runs automatically at set points in an agent's work.
In-context learning
A model picking up a task from examples placed in its prompt.
Initializer agent
The first session's agent, given a special prompt to set up the project.
Invariant
A rule that must always hold in a system.
MCP server
A plug-in service that gives an agent extra tools.
Memory block
A piece of stored text kept in an agent's context to shape behavior.
Multi-tenant
Serving many customers from one system while keeping their data apart.
POSIWID
The saying that the purpose of a system is what it does.
Prompt chain
A series of prompts where each model output feeds the next prompt.
Puppeteer
A tool that drives a web browser from code, used here for testing.
RAG
Retrieval-augmented generation, which adds retrieved documents to the prompt.
Ralph loop
A loop that reruns a coding agent on a goal until the goal is met.
ReAct
A pattern where a model writes out reasoning before acting or answering.
Recursive self-improvement
An AI improving the systems that produce its own intelligence.
Reward hacking
Gaming the reward signal instead of doing the intended task.
Shen
A small statically typed Lisp language with a sequent-calculus type system.
Sub-agent
A separate agent session that does one task and returns only its result.
Terminal-Bench-2
A benchmark of command-line tasks for coding agents.
Token
A small chunk of text that a language model reads and writes.
Viable System Model
A 1970s cybernetics model of five systems that keep an organization stable.
